# Холлоу-Крик — план разработки

Ремейк Godot-прототипа [Zhenya-Kat/hollow-creek](https://github.com/Zhenya-Kat/hollow-creek) на Unity.
Из оригинала берём сюжет, тексты, улики, диалоги, головоломки и игровую логику. Графику и модели делаем заново.

## Решения

| Вопрос | Решение |
|---|---|
| Движок | Unity 6000.6.3f1, URP |
| Управление | От первого лица: WASD + мышь, взаимодействие по прицелу (ЛКМ) |
| Стиль | Стилизованный low-poly, атмосфера за счёт света, тумана и цвета |
| Диалоги | Своя система на данных: вступление + вопросы с условиями и наградами |
| Языки | Unity Localization с первого дня; пока только русский |
| Интерфейс | UI Toolkit (UXML + USS) |
| Камеры | Cinemachine 3 |
| Серые уровни | ProBuilder |
| Ассеты | Только CC0 / свободные лицензии: Kenney, Quaternius, Poly Haven, ambientCG, Freesound (CC0) |

## Принципы архитектуры

1. **Контент — в данных, а не в коде.** Улики, персонажи, диалоги, цели, подсказки, головоломки, обвинение — ассеты (ScriptableObject), редактируемые в Inspector. Добавление контента не требует программирования.
2. **Единое состояние — набор фактов.** Всё, что сделал игрок, — это факты: «есть улика X», «сейф открыт», «говорил с Марой». Любая система спрашивает состояние только через **условия**.
3. **Условия и действия — переиспользуемые кирпичики.** Условие (`HasFact`, `All`, `Any`, `Not`) управляет целями, подсказками, вопросами в диалогах, доступностью обвинения. Действие (`GrantFact`, `OpenPuzzle`, `ShowMessage`, `GoToLocation`) — что происходит при взаимодействии.
4. **Композиция компонентов.** Интерактивный объект = `Interactable` + набор действий. Никаких «божественных» скриптов на 2000 строк.
5. **Системы общаются событиями.** Логика не знает об интерфейсе; интерфейс подписывается на события (`FactAdded`, `LocationChanged`…).
6. **Постоянная сцена + сцены локаций.** `Bootstrap` живёт всегда (игрок, UI, сохранения, звук); локации подгружаются аддитивно и тестируются независимо.
7. **UI как стек экранов.** Верхний экран определяет режим ввода (игра / интерфейс) и курсор.
8. **Разделение на сборки** (Assembly Definitions) с однонаправленными зависимостями; логика покрыта EditMode-тестами.

## Структура кода

```
Assets/Scripts/
  Core/        HollowCreek.Core       — состояние, факты, условия, действия, определения данных, сохранения
  Gameplay/    HollowCreek.Gameplay   — игрок, взаимодействие, осмотр, локации, NPC, логика головоломок
  UI/          HollowCreek.UI         — стек экранов, HUD, дневник, диалог, окна, экраны головоломок
  Editor/      HollowCreek.Editor     — импорт JSON оригинала, редакторы условий/действий
Assets/Tests/EditMode/                — тесты логики
```

Зависимости: `UI → Gameplay → Core`, `Editor → всё`. Core не зависит ни от чего игрового.

### Core
- `FactDefinition` (SO) — любой факт с постоянным Id. `ClueDefinition : FactDefinition` — улика с названием, подзаголовком, текстом (LocalizedString).
- `GameState` — множество полученных фактов, событие `FactAdded`.
- `Condition` (абстрактный, `[SerializeReference]`): `HasFact`, `AllOf`, `AnyOf`, `Not`.
- `GameAction` (абстрактный, `[SerializeReference]`): `GrantFact`, `ShowMessage`, `OpenPuzzle`, `GoToLocation`, `StartDialogue`.
- `CharacterDefinition` (SO) — имя, роль, вступление, список вопросов (текст, ответ, условие появления, действия).
- `ObjectiveSet`, `HintSet` (SO) — упорядоченные пары «условие → текст».
- `PuzzleDefinition` (SO) — параметры головоломки + действия при решении.
- `CaseDefinition` (SO) — подозреваемые, противоречия, правильная пара, условие допуска, текст развязки.
- `SaveSystem` — JSON в `persistentDataPath` с версией формата.

### Gameplay
- `PlayerController` — `CharacterController` + Input System.
- `Interactor` — луч из камеры, подсказка «ЛКМ — осмотреть/поговорить».
- `Interactable` — подпись, условие доступности, список действий.
- `InspectableView` — осмотр крупным планом (Cinemachine-камера вращается/приближается, ограничения задаются на объекте).
- `LocationDefinition` (SO) + `LocationLoader` — аддитивная загрузка сцен, точки появления, двери.
- `Npc` — ссылка на `CharacterDefinition`, поворот к игроку, анимации.

### UI
- `ScreenStack` — открытие/закрытие экранов, переключение карт ввода и курсора.
- Экраны: HUD, Дневник, Диалог, Окно сообщения, Осмотр, Сейф, Фотошкатулка, Штриховка, Обвинение, Главное меню, Пауза.

## Сцены

- `Bootstrap` — постоянная: игрок, камеры, UI, сервисы.
- `Street`, `House`, `Diner` — локации.

## Этапы

| # | Этап | Результат |
|---|---|---|
| 0 | Фундамент | Пакеты (Cinemachine, Localization, ProBuilder), сборки, папки, Bootstrap, загрузка локаций |
| 1 | Ядро | Ходьба, взаимодействие, факты, улики, дневник — в одной серой комнате |
| 2 | Данные | Импорт `evidence.json` / `people.json` в ассеты и таблицы локализации |
| 3 | Диалоги | Система диалогов, NPC-заглушки |
| 4 | Головоломки | Сейф, фотошкатулка, штриховка |
| 5 | Локации | Серые улица, дом, закусочная; переходы; сохранение/загрузка |
| 6 | Сюжет | Цели, подсказки, обвинение, развязка — **игра проходится целиком** |
| 7 | Арт | Модели, текстуры, свет, туман, пост-обработка, звук |
| 8 | Полировка | Меню, настройки, сборка Windows `.exe` |

Графика — только после этапа 6: пока всё на серых кубах, архитектуру менять дёшево.

## Сюжетная логика (из оригинала)

- **Цель по умолчанию:** найти улики возле дома → опросить подозреваемых → открыть сейф → шкатулка и ежедневник → сопоставить мотивы и алиби.
- **Сейф:** код 1031 (дата праздника с афиши, MMDD) → улики `ledger`, `power`, ключ от шкатулки.
- **Фотошкатулка:** требует открытого сейфа; порядок полароидов школа → мост → кладбище → дом → улика `letter`.
- **Стол:** вынуть ящик → взять карандаш → заштриховать три строки → улика `desk` → посветить за планку → улика `tape`.
- **Обвинение доступно** при уликах `alibi`, `power`, `mara`, `owen`, `ledger`, `letter`, `tape`.
- **Правильный ответ:** Эдгар Рид + «Аптека была закрыта в 21:05».
